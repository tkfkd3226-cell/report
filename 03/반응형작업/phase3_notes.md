# 반응형 3차 — 사업성 일반 영역

## 적용
실제 변경 파일: index.html, style.css. common.js는 2차와 바이트 단위 동일하며 ZIP에는 누적 적용 편의를 위해 함께 포함했다.

- 사업성 본문을 business 컨테이너, 설정 카드를 business-settings 컨테이너로 지정.
- 본문 1600px 초과: 기존 설정 카드 43:17:40 유지. 이하: 기본 설정 한 줄, 인건비/소모품비와 산정 기준은 다음 줄 1:2.
- 설정 카드 자체가 600px 이하이면 기본 설정/산정 기준 내부를 한 열로 전환. 작은 Tablet에서 산정 기준의 라벨과 값이 겹치는 것을 피하기 위한 컴포넌트 기준.
- Phone 760px 이하: 설정 카드와 내부 필드를 모두 한 열로 배치. 라벨 아래 입력창 전체 폭 사용.
- 입력창 142px, 스텝 버튼 26px, 합계 168px를 공통 ba 토큰으로 관리. 좁은 화면에서는 일반 입력창 최소 110px, 스텝 포함 최소 136px를 기준으로 수축.
- 1안/2안 설명은 본문 1600px 이하에서 균등 2열과 문장 줄바꿈, Phone에서는 1열.
- 참고자료는 본문 1300px 이하에서 월 인건비/업그레이드 카드를 한 열로 배치.
- 참고표에 동일한 스크롤 wrapper 2개만 추가. 기존 생성 대상과 입력 노드 구조는 유지. Phone에서 내부표 최소폭 640/660px 및 첫 열 sticky 적용. 첫 셀 배경은 행 높이 전체를 덮도록 stretch 처리.
- Phone 참고 합계는 긴 금액 표시를 위해 2x2 배치.

## 기준 및 보존
- viewport breakpoint 추가 없음: 기존 760px 사용. 1600/1300/600px은 실제 콘텐츠/카드 너비 기준.
- 1600px은 43:17:40 카드의 라벨/컨트롤 폭, 1300px은 참고표 두 개의 금액/입력 열 확보, 600px은 설정 카드 내부 2열의 최소 공간을 근거로 정했다. 실제 화면에서 경계 조정 필요 여부는 미검증이다.
- 1920px 가용폭에서는 기존 카드 비율, 입력창 142/168px, 설명 카드 560px를 유지하도록 구성.
- 스냅샷의 .is-ba-snapshot은 Phone 전용 규칙에서 제외. 보고용 1702px 외곽/1666px 내부 폭에서는 넓은 컨테이너 배치 유지.
- Print는 screen 전용 배치를 제외하며 참고표 wrapper overflow는 visible로 설정.
- 계산, 초기화, stepper 이벤트, tooltip, RS matrix, hover, Fixed Header, 스냅샷 JS 변경 없음.

## 미검증 / 실기 확인
브라우저 실행 파일이 없어 레이아웃 실측, 실제 입력/스크롤/sticky, PNG 출력, Print를 검증하지 못했다.
- 1920px: 기존 설정 3개 한 줄, 설명 카드와 참고자료 기준 모습 확인.
- 1600/1440/1101/1100/761px: 기본 설정 + 하단 2개, 카드 내부 줄바꿈, 금액 입력창 잘림 여부 확인.
- 760/390px: 설정 1열/라벨 아래 입력창, 스텝 버튼 작동, 설명 1열, 참고표 내부 스크롤과 첫 열 배경/경계선 확인.
- Phone에서 스냅샷 다운로드: 넓은 Desktop 출력과 입력값 보존 확인.
- RS 간격 전환과 matrix sticky는 4차 대상. 정산 반응형은 5차 대상. 전체 페이지 가로 넘침 해소는 아직 완료 판정하지 않음.
